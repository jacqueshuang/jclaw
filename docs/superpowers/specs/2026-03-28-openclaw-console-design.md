# OpenClaw Console 设计规范

## 背景
当前仓库已经被做成了一个任务处理型桌面工具，但用户真正希望构建的是一个 **OpenClaw 桌面控制台**。这个产品的核心不是任务流，而是围绕 OpenClaw 提供一个具备商业化界面的桌面入口：应用启动后先检测 OpenClaw 是否已安装；若未安装，首页主按钮显示“安装”；若已安装，主按钮显示“已安装”。在这个基础上，产品还需要承接后续的 **Skills 管理、Channel 管理、Agent 管理**。

这意味着产品方向需要从“任务工具”切换为“安装器内嵌控制台”：安装能力是首页第一优先级，但产品整体仍是完整控制台，而不是单一安装器。

## 产品定位
OpenClaw Console 是一个基于 **Tauri + Vite + Vue + Rust** 构建的桌面控制台，首版支持：
- macOS
- Windows

产品采用 **安装器内嵌控制台** 的结构：
- 首页优先展示 OpenClaw 安装状态
- 左侧固定一级导航：安装 / Skills / Channel / Agent
- 安装模块负责 OpenClaw 的检测、在线安装、离线安装与状态反馈
- Skills / Channel / Agent 作为后续能力承接模块，以产品级骨架和状态展示为首版目标

## 首页结构与交互
### 视觉方向
首页采用商业化深色控制台风格：
- 深色背景
- 强层级
- 高级感
- 安装状态作为第一焦点
- Skills / Channel / Agent 作为摘要承接区域

用户已确认该方向可作为首页视觉基线。

### 布局结构
- 左侧固定导航：
  - 安装
  - Skills
  - Channel
  - Agent
- 主区域顶部：
  - OpenClaw 安装状态标题与状态 badge
- 主区域核心卡片：
  - 若未安装：主按钮显示“安装”
  - 若已安装：主按钮显示“已安装”
- 次级卡片：
  - 在线 / 离线安装模式说明
  - Skills / Channel / Agent 状态摘要

### 启动行为
应用启动后：
1. 加载本地配置与缓存状态
2. 执行 OpenClaw 安装检测
3. 根据检测结果渲染首页
4. 再允许用户进入各模块

## 安装模块设计
安装模块是首页第一优先级模块，负责 OpenClaw 安装状态机。

### 安装状态
首版只定义 5 个清晰状态：
1. 检测中
2. 未安装
3. 安装中
4. 已安装
5. 安装失败

### 已安装判定
“已安装”的判断方式为：
- 检测本机固定安装目录或 OpenClaw 可执行文件是否存在

不以服务可启动或完整运行环境校验作为首版已安装标准。

### 在线安装
默认安装流程为在线安装：
1. 获取下载源信息
2. 下载 OpenClaw 安装资源
3. 解压或写入固定安装目录
4. 校验目标文件存在
5. 更新状态为“已安装”

### 离线安装
同时支持离线安装：
1. 用户选择本地安装包
2. 应用校验文件格式
3. 解压或复制到固定安装目录
4. 校验目标可执行文件存在
5. 更新状态为“已安装”

### 安装模块页面表现
安装中状态共用一套 UI，区别只在安装来源不同：
- 显示当前步骤
- 显示简化进度
- 显示日志摘要
- 首版不强制加入取消安装

### 错误类型
首版只处理用户能理解的错误：
- 网络错误
- 文件错误
- 权限错误
- 校验错误

错误展示需包括：
- 错误标题
- 一句可理解原因
- 明确下一步动作（如重试、重新选择离线包）

### 安装完成后的首页变化
安装完成后：
- 状态 badge 从“未安装”切换为“已安装”
- 主按钮从“安装”切换为“已安装”
- 在线 / 离线安装说明弱化
- Skills / Channel / Agent 摘要保留

首版不要求首页在“已安装”状态立即变成“启动 OpenClaw”或“打开 OpenClaw”。

## 模块边界设计
### 安装模块
负责：
- 安装检测
- 在线安装
- 离线安装
- 安装状态维护
- 安装结果写回本地状态

不负责 Skills / Channel / Agent 的业务本体。

### Skills 模块
负责：
- 展示技能列表
- 展示技能启用/禁用状态
- 为未来安装、导入、本地管理预留能力

首版目标：
- 列表骨架
- 空状态 / 未配置状态

### Channel 模块
这里的 Channel 采用 OpenClaw 官方定义，不是下载源或分发源。

Channel 的正确含义是：
- OpenClaw 接入外部聊天平台的渠道层
- 通过 Gateway 对接不同聊天平台
- 支持不同平台的消息收发与接入能力

Channel 模块负责：
- 管理聊天渠道
- 展示渠道连接状态
- 展示平台能力差异
- 提供配置、启停、授权、配对、诊断入口

首版 Channel 模块应体现：
1. 渠道列表
2. 渠道状态（未配置、已配置未连接、连接中、已连接、异常）
3. 能力展示（文本、媒体、群组、回应、编辑、撤回等）
4. 接入入口（新增、配置、重连、查看日志）

### Agent 模块
负责：
- 展示 Agent 列表
- 展示实例状态
- 为未来模板管理、运行管理、配置管理预留空间

首版目标：
- 列表骨架
- 空状态
- 实例状态摘要

### 系统层
这是桌面应用的共享底层能力，不单独作为导航模块暴露。包括：
- Rust / Tauri 系统能力
- 本地文件检测
- 安装目录写入
- 文件选择器
- 本地状态存储
- 统一 command 接口

前端 Vue 不直接操作系统，所有系统行为均通过 Tauri command 调用 Rust。

## 模块关系
- 首页读取安装模块状态
- 首页摘要展示 Skills / Channel / Agent 的轻量状态
- 安装模块通过系统层执行文件检测、安装、写入与校验
- Skills / Channel / Agent 通过统一状态层读取本地数据
- 首版不要求模块之间形成复杂强耦合

## 首版范围
### 首版必须交付
1. 商业化首页控制台
2. 安装状态检测
3. 在线安装流程
4. 离线安装流程
5. 安装中 / 安装失败 / 已安装状态反馈
6. 4 个一级导航模块
7. Skills / Channel / Agent 的产品级骨架与状态展示

### 首版明确不做
- 不做完整聊天会话系统
- 不做复杂 Agent 编排器
- 不做完整 Skills 市场生态
- 不做多层权限系统
- 不做 Linux 支持
- 不做复杂远程部署系统
- 不做完整自动更新平台

## 首版成功标准
首版被认为成功，当且仅当满足：
1. 桌面应用打开后，产品形态明显是 OpenClaw 控制台，而不是任务工具
2. 首页为用户提供商业化控制台体验
3. 应用能正确检测 OpenClaw 是否已安装
4. 用户在未安装时能完成在线安装或离线安装
5. 安装完成后首页能切换为“已安装”状态
6. Skills / Channel / Agent 已具备清晰的一级模块与管理骨架

## 推荐实施顺序
1. 先重建首页与安装模块
2. 再完成安装状态机与 Rust 系统命令
3. 再搭建 Skills / Channel / Agent 三个模块骨架
4. 最后统一本地状态层与导航体验
